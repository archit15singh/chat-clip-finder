# Studio verification gates

These are the first five gates because failures here can send the wrong cut public, lose a campaign deadline, or train the next edit on misleading feedback.

| Gate | Evidence required | When it fails |
| --- | --- | --- |
| **1. Source and edit** | New packages name the used spans on the source clock and the expected runtime, hook and payoff on the export clock. Staging compares spans, duration and sampled frames. The independent reviewer records source and reuse evidence and explains both beats against the frozen package. | Return to the source or edit. Regenerate the review and reapprove a changed package. |
| **2. Sound** | The decoded file has measurable signal in a track covering the picture. An intentionally silent export has no track and has a written reason. A reviewer checks the actual mix, correct voices, sync and rights. | Restore or replace cleared sound, then render and review again. Audio measurements alone cannot establish sync or rights. |
| **3. Before upload** | The uploader reads the signed-in account and supplies the exact approved package and file it will select. The queue compares the account and file hash before any browser change. A paid cut also reruns its sealed campaign's eligibility evidence, source, account and deadline checks. | Leave the delivery claimed and correct the evidence or handoff. Release the claim if someone else should take it. |
| **4. Public playback** | Open the actual public permalink and verify copy, visibility, runtime, opening, payoff and sound on the player, with volume on. | Keep the attempt in reconciliation if the post or playback outcome is uncertain. Reopen the same post before any retry. |
| **5. Downstream evidence** | Campaign handoffs must bind the same reviewed cut to its declared campaign. Distribution checks the actual venue, including Reddit communities and Discord channels. Analytics checks the true post age before accepting a milestone label. | Keep an unverified placement or submission out of the results. Save an early or late sample at its real age. |

Use the [queue guide](publishing-queue.md), [campaign workflow](paid-campaign-workflow.md), [distribution guide](studio-distributor.md), and [round log](studio-rounds.md#read-back-performance-at-comparable-ages) for the handoff fields. The browser operator and reviewer supply what they actually observed. The code can validate those observations against the recorded package and receipts.
